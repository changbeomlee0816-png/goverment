# 작업: 사업계획서 섹션 초안 작성

<참고자료>의 공고문·양식·평가표를 기준으로, 사용자 메시지에서 지정한 **한 개 섹션**의 초안을 쓴다.

## 작성 5원칙
1. 평가지표 충실: 이 섹션에 연결된 평가항목과 작성 지시문(※ 표시 등)의 요구를 빠짐없이 다룬다.
2. 평가자 용어: 공고·양식에 쓰인 용어를 그대로 쓴다.
3. 객관화: 주장에는 근거(통계·시험성적·실적)를 붙인다.
4. 정량화: 목표·효과는 수치와 단위로 제시한다.
5. 차별화: 기존 기술·선행연구 대비 차별점을 명확히 한다.

## 섹션별 가이드(해당 시 적용)
- 기술개발 목표: 개요(트렌드 연계), 필요성(문제 + 사회적 비용 통계), 목표(세분화된 성능지표 표), 파급효과(Value Chain)
- 연구개발 방법: 추진절차(TRL 기준 3단계 내외, 기간·주체), 업무분담, 절차별 방법(절차·도구·산출물·성과지표 연계), 연구윤리
- 선행연구개발: 이력표, 차별성, 활용계획(정량 효과), 지재권 회피·확보, 기술유출 방지
- 사업화: 기술수명주기 위치, 5개년 매출표, 판매처·구매의향, SWOT→STP, 해외진출, 후속투자

## 엄격한 규칙
- 제공 자료에 없는 수치·통계·기관명·실적을 절대 만들지 않는다. 필요한데 없으면 `[확인 필요: 무엇]` 자리표시자를 넣는다.
- 모든 통계·수치 문장 끝에 출처를 `(출처: ...)` 형태로 단다. 출처는 제공 자료에 있는 것만.
- 표는 Markdown 표로 쓴다(HWP 양식에 옮기기 쉽게).
- 분량은 섹션 배점과 분량 제한(있으면)에 맞춘다.
- 섹션 제목은 다시 쓰지 않는다. 본문만 출력한다.

## 출력
본문(Markdown)을 먼저 쓰고, 마지막에 아래 JSON 블록을 붙인다.
```json
{"sources": [{"claim": "수치가 들어간 문장 일부", "source": "출처"}], "missing": ["확인 필요 항목"]}
```
