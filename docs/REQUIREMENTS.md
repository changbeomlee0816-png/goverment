## 4. 기능 요구사항

### 4.1 기업정보 등록
- 수동 입력 폼 + 사업자등록증·재무제표 업로드 시 자동 추출(추출값은 사용자 확인 후 저장)
- 서류 보관함과 연동, 유효기간 30일 전 알림

### 4.2 아이템 포트폴리오
- 요약맵 입력: 이슈 → 성능지표 → 측정방식 순서로 입력 유도
- Discovery/Project/Asset 구분, 우선순위, 목표 TRL
- NTIS 연관과제 검색 버튼: 유사 과제명·성능목표를 가져와 벤치마킹 참고(참고용 표시, 자동 입력 금지)

### 4.3 공고 수집
- 배치: 기업마당·K-Startup 1일 1회(설정 가능), 원본은 `data/snapshots/YYYYMMDD/`에 저장
- 중복 제거(제목+기관+접수기간 기준)
- 공고 상세에서 자격요건을 LLM으로 추출 → `EligibilityRule`에 원문 근거 문장과 함께 저장 → 사람이 "확인" 체크
- 연초 자료(예산기금운용계획, 합동설명회) 업로드 시: 3월 이후 사업, 신규·단상·단하 사업, 수혜자 키워드로 필터해 "연간 후보 리스트" 생성

### 4.4 매칭 엔진
1단계 하드필터(규칙 코드): 업력, 소재지, 매출·인원, 업종, 필수 인증, 접수 마감 여부 → 불충족 시 사유 표시

2단계 점수화(0~100, 가중치 설정 화면 제공):

| 차원 | 기준 예시 | 기본 가중치 |
|---|---|---|
| 목적 적합도 | 아이템 이슈·키워드와 사업목적 유사도 | 30 |
| TRL 적합도 | 사업이 요구하는 단계와 아이템 현재·목표 TRL 일치 | 20 |
| 규모·기간 적합도 | 지원금액·기간과 아이템 예산·개발기간 | 15 |
| 역량 | 부설연구소, 연구인력, 선행 R&D, 특허 | 20 |
| 가점 | 지역, 인증, 기업 특성 가점 | 15 |

3단계 LLM 설명: 점수표를 입력으로 받아 "추천 이유 1~2줄" 생성(점수 변경 금지)

출력: 부처/지자체 분리, R&D·비R&D 태그, [사업명][접수기간][지원규모][점수][이유][원문링크], 마지막 요약표, 하단 고지 "최종 자격 확인은 공고 원문과 주관기관 기준"

### 4.5 신청 관리
- 칸반(상태별) / 리스트 / 캘린더 3가지 보기
- 마감 D-14, D-7, D-3 알림(이메일 또는 화면 배너)
- 사업별 필수 제출서류 체크리스트(공고에서 추출) + 서류 보관함 자동 매칭, 발급처 안내

### 4.6 사업계획서 작성
- 작성 순서: ① 공고·평가표 로드 → ② 평가항목별 요구사항 추출 → ③ 부족 정보는 AI가 질문(인터뷰형) → ④ 섹션별 초안 → ⑤ 사용자 수정
- 섹션 템플릿(교육 기준):
  - 기술개발 목표: 개요(트렌드 연계·도식), 필요성(문제+사회적 비용 통계), 목표(세분화된 성능지표), 파급효과(Value Chain)
  - 연구개발 방법: 절차(TRL, 3단계 내외, 기간·주체), 업무분담 총괄표, 절차별 방법(절차·도구·산출물·성과지표 연계), 연구윤리
  - 선행연구개발: 이력표, 차별성, 활용계획(정량 효과), 지재권 회피·확보, 기술유출 방지
  - 사업화: 기술수명주기 위치, 5개년 매출표(A=B+D, C=B/A×100), 판매처·구매의향, SWOT→STP, 해외진출, 후속투자
- 보조 도구: 시장규모 계산(TAM-SAM-SOM), 매출 예측표 자동 계산, 성능지표 표, 역할분담표
- 모든 통계·수치에 출처 필드 필수, 출처 없는 문장은 노란색 표시
- 내보내기: DOCX(표준양식 순서), 섹션별 복사(HWP 양식에 붙여넣기용)

### 4.7 자체 점검(레드팀)
- 규칙 점검: 평가항목 누락, 정량 수치 없는 목표, 성능지표–절차 미연계, 출처 없는 통계, 분량 불균형(배점 대비)
- LLM 가상 채점: 평가표 항목별 탁월~불량 + 근거 + 수정 제안 문장
- 외부 계획서(PDF/HWP) 업로드 점검도 지원
- 부서별 검토 요청 체크(개발/생산/영업)

### 4.8 설정
- 매칭 가중치, 수집 주기, 관심 지역·분야 해시태그, 알림 수신자
- 프롬프트 파일 버전 관리(`app/llm/prompts/*.md`)

## 5. 프롬프트 설계 (파일로 분리)

| 파일 | 역할 |
|---|---|
| `extract_eligibility.md` | 공고 원문 → 자격요건 JSON(필드, 조건, 근거 문장). 원문에 없으면 null |
| `match_reason.md` | 점수표 → 추천 이유 1~2줄. 점수·자격 판정 변경 금지 |
| `interview.md` | 평가항목 대비 부족 정보를 질문 목록으로 생성 |
| `section_writer.md` | 섹션별 초안. 작성 5원칙(평가지표 충실, 평가자 용어, 객관화, 정량화, 차별화) 적용, 제공 자료 외 수치 생성 금지 |
| `reviewer.md` | 평가위원 페르소나로 항목별 채점과 수정 제안 |

공통 페르소나: 정부·지자체 지원사업 전문 컨설턴트, 공신력 있는 문체, 즉시 실행 가능한 간결한 정보.
공통 규칙: 제공된 자료만 근거로 사용, 근거 문장 인용, 모르면 "확인 필요".

## 6. 비기능 요구사항
- 보안: 기업정보·계획서는 로컬 DB 저장, API 키 `.env` 관리, 로그에 개인정보·키 미기록
- 출처 추적: 공고·수치·추천마다 원문 파일/URL 기록
- 한글 문서(HWP) 텍스트 추출 지원
- 양식·평가표 연도별 버전 관리
- 성능: 공고 수백 건 매칭 수 초 이내(규칙 필터 먼저, LLM은 상위 N건만)

## 7. 단계별 완료 기준 (Claude Code 체크포인트)

| 단계 | 완료 기준 |
|---|---|
| 1. 기반 | 기업·아이템·성능지표 입력/수정/삭제, SQLite 저장 확인 |
| 2. 수집 | 기업마당 API 1회 수집 → 스냅샷 저장 → 공고 목록 화면 표시, PDF 공고 업로드 후 텍스트 추출 |
| 3. 매칭 | 샘플 기업 1개로 하드필터 + 점수 + 보고서(부처/지자체 분리, 요약표) 출력, pytest 통과 |
| 4. 작성 | 공고 1건 선택 → 인터뷰 질문 → 섹션 초안 → DOCX 내보내기 |
| 5. 점검 | 초안 또는 업로드 문서에 대해 누락 항목 목록과 항목별 가상 점수 출력 |
| 6. 관리 | 칸반·캘린더, 마감 알림, 서류 보관함 유효기간 알림 |

## 8. Claude Code 지시 예시

```
1) CLAUDE.md와 docs/REQUIREMENTS.md를 읽고, 7장 1단계(기반)의 구현 계획과 변경 파일 목록을 먼저 보여줘.
2) 1단계를 구현하고 샘플 기업(에너지 관리 솔루션 기업) 데이터로 실행 확인해줘.
3) 2단계: 기업마당 API를 1건 호출해서 응답 원본을 저장하고, 그 구조를 보고 파서를 만들어줘.
4) 3단계: rules.py·scoring.py를 만들고 pytest 테스트까지 작성해줘. 가중치는 설정 파일로 빼줘.
```
